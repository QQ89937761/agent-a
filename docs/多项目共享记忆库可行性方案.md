# 多项目共享记忆库可行性方案

日期：2026-10-16。状态：微信多库与第二阶段飞书接入源码已实现；尚未打包或部署到生产云端，真实多账号联合验收待条件具备。

## 结论和建议范围

可行。现有独立账号身份、共享指令、SQLite 存储和云端管理入口可以复用。不能只增加库名称和账号勾选框：资料检索、写入、账号认证、备份下载、worker 转发和删除同步都必须按库隔离。

建议第一阶段支持微信多个项目库、各库管理员及账号只读授权。飞书已接入同一权限模型，但不能把微信和飞书的同名备注视为同一个人。不增加向量数据库、独立数据库服务或新的后台服务。

## 第一阶段已实现范围

- 微信每个账号的私人记忆继续独立；项目库采用 SQLite 权限目录与按不变 ID 命名的独立资料文件。
- 设置 → 消息连接 → 项目共享记忆库：选择、新建项目库，修改显示名称和调用名称，指定管理员，勾选只读成员；列表显示编号、备注和遮罩标识。
- 新库仅管理员可访问，其他账号必须明确授权；管理员权限仅限本库。新连接账号不自动加入已有项目库。
- 原共享库一次性迁移为“公司公共资料”，保留资料、原编号、原调用名称和管理员；迁移时已有账号保留只读权限，之后新增账号默认无权。已有资料先生成迁移前备份，不删除私人记忆。
- 指令在进入模型、普通历史及自动记忆前处理，只查询指定库。名称与指令之间必须有空格或冒号；原名称在重命名后只提示更名，不再执行、也不分配给其他项目。
- 云端判断权限和执行指令，断线不使用旧本机项目副本；worker 每条普通微信消息先让云端判断是否为项目指令，不缓存完整项目资料或权限。紧急锁定及停止任务不依赖这一步。
- 自动上传/下载不含项目资料和权限目录；旧 hub 返回项目文件时，新 worker 也会过滤，自动导入不恢复项目资料。此前已合法下载的文件与历史备份不会被自动删除，管理者需自行清理。
- “备份全部项目库到本机”需明确确认：云端通过已登记的专用管理 SSH 密钥获取，不使用普通执行连接口令。手动项目备份单独放在备份目录的 `project-libraries` 子目录，按现有保留份数轮换，避免频繁私人记忆备份挤掉项目备份。
- 删除需输入完整调用名称，清空当前库资料、撤销读成员并停用；旧上传/自动快照不能复活本库。删除名称保持保留，重新使用须新建空库并使用不同调用名称，避免旧指令意外访问另一项目。
- 不提供自动恢复项目备份，也不做离线项目查询；恢复需要管理者核对目标、成员和删除状态后人工处理。飞书已接入；跨渠道自动账号关联与维护角色尚未开放。

## 第二阶段：飞书接入同一项目库

- 在“消息连接”中使用统一的“项目共享记忆库”区，不在微信、飞书卡片内重复一套配置；可为同一个库明确选择微信或飞书管理员及只读成员。
- 选择项显示“渠道＋编号＋备注＋遮罩标识”，真正授权依据是稳定身份。飞书身份包含 App ID 和 Open ID；同名、相同字符串 ID 或同序号均不自动关联。
- 飞书项目指令从已认证私聊回调取得真实发送者，聊天会话的 chat_id、消息正文、前端备注均不是身份证明。查询不进入模型、普通对话历史或自动记忆。
- 新授权飞书用户不自动加入任何库。移出飞书白名单立即阻止访问，即使项目内尚留其旧授权；重新加入白名单视为原身份恢复，若需永久撤权还应取消对应项目成员。
- 更换 App ID 后不继承原应用权限。旧文本/语音/图片回调携带收到事件时的应用标识；排队任务若在切换应用后完成会停止，不重新解释为新应用用户。
- 云端飞书消息由 hub 认证并执行，本机 worker 不使用旧项目副本，也不新增可通过正文伪造飞书身份的转发 API。
- 云端统一项目状态及修改走专用管理 SSH；旧服务缺少跨渠道能力时明确提示更新。旧微信专用设置接口不允许覆盖含飞书成员的项目权限。
- 原有项目文件、编号、微信权限和全量备份隔离机制继续复用。不迁移或宣称重做飞书原有私人长期记忆体系，本阶段只接入显式项目库。

## 信任边界

微信发送者由已认证的 iLink 消息回调获得；worker 是受信任的消息转发端，后端同时核对账号与稳定身份绑定，再按实际发送者检查本库权限。执行口令不等于全量备份权限，但它也不是对恶意 worker 的独立身份签名系统；持有服务器 SSH 或电脑操作系统权限的管理员仍可直接接触磁盘资料，项目权限不是操作系统沙箱。

首期设置只允许从本机管理，云端设置经专用 SSH 操作；不允许从普通聊天修改成员、自我授权或以备注冒充真实账号。

## 使用方式

在设置中提供一个统一的“项目共享库”管理区，先选择库，再配置资料和账号。微信、飞书的连接和远程操控开关仍在原处。

每个库至少显示：库名称、调用名称、状态、管理员、授权账号和权限、资料条数。授权列表复用“编号＋备注＋用户标识”，不以编号或备注作为授权依据。

示例：

| 项目库 | 调用名称 | 管理员 | 可查询账号 | 调用示例 |
| --- | --- | --- | --- | --- |
| 公司公共资料 | 公司资料 | 办公室账号 | 指定的员工账号 | 公司资料 查询：报销流程 |
| 甲项目 | 甲项目资料 | 甲项目负责人 | 甲项目成员账号 | 甲项目资料 查询：混凝土强度 |
| 乙项目 | 乙项目资料 | 乙项目负责人 | 乙项目成员账号 | 乙项目资料 查询：交付时间 |

调用名称只负责选择资料库，不授予权限。允许一个账号访问多个库；未授权用户即使知道名称、资料编号，也不能查询、列表、保存、修改、删除或下载该库。

建议保留显式调用方式。普通聊天不自动搜索全部项目；第一阶段不自动将查询结果加入后续普通聊天历史，减少跨项目资料混用。若后续允许带入上下文，历史、缓存和工具调用上下文也必须按“账号＋库 ID”隔离。

## 权限规则

| 权限 | 可做的操作 |
| --- | --- |
| 未授权 | 不提供资料、列表、导出、文件或其他项目内容 |
| 查询 | 查询、列表 |
| 维护 | 查询、保存、修改和删除单条资料 |
| 库管理员 | 维护资料、管理本库成员和权限 |
| 本机管理者 | 在受保护的本机设置中创建库、指定管理员、删除和恢复库 |

第一阶段可先只开放“查询”和“管理员”两档，避免一开始增加过多开关；后续确有分工需要再开放“维护”。创建库时默认仅管理员有权，其他账号必须明确授权。

- 资料权限与远程操控权限分开。关闭电脑远程操控的账号仍可按授权查项目资料；开启远程操控不自动获得项目库权限。
- 按真实身份授权：微信用已认证的微信身份及账号绑定关系；飞书用应用标识＋Open ID。跨渠道身份关联需要明确确认。
- 管理员解绑后保留身份，不自动转给列表第一人；通过本机设置重新指定管理员。
- 转发接口从可信连接中确定真实身份，拒绝把消息正文、前端选项、备注或调用名称当成身份凭证。
- 首期权限管理仅在本机设置进行，不允许通过普通聊天自我授权或任意修改成员权限。

## 最小技术实现

采用一个 SQLite 元数据库保存库、成员权限及审计，每个项目一个独立 SQLite 资料文件。文件名使用系统生成的不变库 ID，不直接采用用户输入的名称。

- `libraries`：不变库 ID、显示名称、唯一调用名称、管理员、只读稳定身份列表、启用状态和权限版本；两种角色使用同一条库记录事务更新，首期不额外拆成员表。
- `aliases`：已更名调用名称与原库绑定，只返回更名提示，禁止重新分配。
- 独立资料文件：继续复用现有资料编号、内容、创建者和时间字段；保留资料编号在单库内唯一。
- 变更记录：创建、重命名、授权/撤权、写入、删除及恢复，记录真实操作者和时间，不把完整资料或凭据写入普通日志。

调用路径：识别明确调用名称 → 解析不变库 ID → 校验真实账号及库状态、权限 → 只打开对应库执行操作 → 返回结果。权限必须在后端执行前校验，不能仅靠前端筛选或提示词约束。

名称在同一服务实例中唯一；优先采用“调用名称＋空格或冒号＋指令”的明确边界，避免名称互为前缀时选错库。重命名不改变库 ID 和资料归属，旧名称不继续暗中访问另一个库。

## 云端、本机与同步

有云端连接时，项目查询和授权判断以云端为准；断线时共享库查询明确失败，不能自动回退到旧本机副本以绕过撤权。

必须把“管理者的全量备份”与“普通账号的可查询资料”分开：

- 普通账号/执行 worker 不因连接成功就下载全部项目库。
- 完整备份仅允许明确具有全量备份权的受信任管理设备；备份能力单独授权，不能复用普通聊天账号权限。
- 若需要普通设备离线查询，必须仅同步其获授权的库，携带库 ID、权限版本、删除标记；撤权后清除缓存并禁止离线回退。已被合法下载的资料无法通过远程撤权保证彻底收回，第一阶段建议不提供此功能。
- 删除库要发布删除状态；旧 worker 上传、合并和旧快照不能自动复活资料或权限。人工恢复备份须由管理者明确操作，并重新检查成员权限。

## 旧数据迁移与删除

现有共享库迁移为一个默认项目库，保留所有资料、原编号、调用名称及管理员。迁移前备份；迁移失败不删除或覆盖原资料，明确报错并停止项目访问，由管理者检查后重试，不借旧权限绕过校验。私人记忆不删除。

为避免升级后突然中断业务，迁移时可一次性把现有已授权微信账号登记为默认库的只读成员，并在首次打开设置时明确展示成员供管理者复核；之后新账号不自动获得任何项目库权限。新建项目库始终默认拒绝。管理员应在迁移后复核一次默认库成员。

“删除库”和“删除单条资料”分开。删除库须显示库名称、资料条数和影响范围，输入名称确认后清除内容、撤销成员访问并停用。已有历史备份独立管理，界面必须说明备份不会自动删除。恢复时恢复到明确目标库，避免与其他项目自动合并。

## 实施顺序和验收

1. 完成本次单库调用名称、删除及同步状态的改动。
2. 引入多库元数据和独立资料文件，迁移默认库；此时先不开放多库生产使用。
3. 实现微信按库授权和本机管理界面，同时收紧全量同步、备份和 worker 转发；源码已完成，部署前仍需用测试账号进行实际微信与云端联合验收。
4. 飞书已按同一规则接入；维护角色、资料导入、离线查询与跨渠道身份绑定仍留待明确需要时实施。

上线前必须验证：账号 A 不能读取/修改项目 B；同名备注和相似编号不导致串库；多库相同资料编号相互隔离；重命名不丢资料；撤权立即生效；删除后旧快照不复活；新扫码身份不会冒用旧权限；只读账号不能借转发接口写入；本机和云端版本不兼容时清楚报错；非管理设备不能下载全量项目备份。

现已在“微信多项目库＋管理员＋只读成员”基础上接入飞书，权限与同步边界一并验证。技术可行，主要工作量在权限和同步边界，远大于增加名称输入框。

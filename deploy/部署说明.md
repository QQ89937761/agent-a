# 小A 云端部署说明

目标是让云端 hub 常开，本地悬浮小A作为 worker 主动连接。电脑关机时云端仍可对话、查记忆并使用服务器侧工具；电脑开机后才会把本机 Office、文件和桌面操作交给 worker。

## 路线 A（推荐：免域名、受信任的 IP 网页证书）

无需购买域名。公网 HTTPS/WSS 入口默认使用 `1115` 端口，被占用时自动选择空闲端口，网页和本机 worker 共用这一入口；后端只监听服务器回环地址，不提供第二个公网入口。每位用户的 IP 和实际网页端口自动保存并显示在“电脑与安全 → 网页访问密码”。

公网 TCP `80` 必须持续可达，用于 Let's Encrypt HTTP-01 验证和续期；另外放行统一的 HTTPS/WSS 端口。网页不必使用 `443`。已有 Nginx 会复用，只添加小A自己的 IP 虚拟主机；没有 Nginx 时自动安装。如果 `80` 被其他非 Nginx 程序占用，或已有 IP 虚拟主机冲突，部署会报错，不会停止其他程序。云厂商安全组需用户放行，脚本无法代替云控制台。

在服务器上传项目后执行（第一个参数是公网 IP）：

```bash
cd /opt/xiaoa
sudo bash deploy/deploy_hub.sh 203.0.113.10
# 内部 hub 默认从 1004 起寻找空闲回环端口；公网入口默认使用 1115。
```

脚本自动生成随机 `AGENT_HUB_TOKEN` 和网页密码，保留或生成 Nginx 到回环后端所需的内部证书，并在独立环境 `/opt/xiaoa-acme/venv` 安装 Certbot 5.4+。首次先用测试 CA 验证 IP，再申请正式短期证书（有效期约 160 小时）。`xiaoa-ip-cert-renew.timer` 每 12 小时检查续期，支持停机后补执行；续期成功后验证 Nginx 配置并平滑加载，不重启 hub。

统一入口优先使用 `1115`，被占用时从 `1116` 起自动寻找空闲端口；以部署后显示的实际地址为准，例如 `https://服务器IP:1115`，worker 为同一入口的 `wss://服务器IP:1115/worker`。`XIAOA2` 连接串使用系统 CA、IP SAN 和有效期校验，不锁定叶证书指纹；续期换证后自动重连仍正常。没有设置网页密码时远程页面、API 和聊天连接仍禁止访问。

连接串和网页密码由部署流程通过 SSH 自动读回并删除临时文件，不打印到部署日志；不要把这些凭据发给别人。

新版连接串包含服务器地址、端口、CA 验证方式和握手口令，并有校验段；少一个字符会在本机提示“连接串校验失败”。设置页只回显地址、端口和指纹前缀，不回显完整口令。换电脑或重装系统时粘贴同一串即可；连接串丢失可在服务器重新打印：

```bash
sudo bash deploy/deploy_hub.sh rotate-token
```

该命令会生成新口令、重启 hub，旧连接串立即失效。把新串重新粘贴到每台 worker。IP 证书自动续期不需要重新粘贴连接串，客户端每次连接都会校验新证书。


## 设置页一键部署、更新与维护

设置页的“部署 / 更新云端”会把当前安装包上传到目标服务器，按“检查服务器 → 上传安装文件 → 安装运行环境 → 更新配置与启动服务 → 检查云端服务 → 连接本机 worker”六步执行。上传阶段显示真实字节进度，任务状态保存在本机，关闭设置页后可恢复查看。

- 首次部署需要远程密码；成功后仅保存这台服务器专用 SSH 密钥，密码不落盘。后续部署可留空密码。
- 更新先校验安装包并创建回退点，健康检查通过后才提交；失败自动恢复代码、配置和运行环境，保留数据、记忆、证书和飞书记录。
- 云端已健康但 worker 未上线时显示“部分成功”，可以只重试 worker，不重复上传。
- “高级维护”提供只读检查、保留数据的修复/重装，以及默认保留数据的卸载。彻底删除数据必须额外输入确认文字；会移除小A自己的 Nginx 网页入口和 IP 续期任务，但不会卸载 Nginx、停止其他网站或修改云厂商安全组。
- 自动维护目标为 Debian/Ubuntu + systemd，并需要 root 或免密 sudo。云厂商安全组仍需手动放行实际显示的 TCP 端口。

## 路线 B（域名 + Let's Encrypt + Nginx）

适合已有域名并希望浏览器使用公有 CA 的情况。先运行 `deploy/deploy_hub.sh <公网IP> <自定义端口>`，再按原流程配置域名反向代理（第三个参数传同一个 hub 端口）：

```bash
sudo bash deploy/configure_tls.sh xiaoa.example.com you@example.com 1004
```

这条路线由 Nginx 接收 `443` 并转发到 hub；worker 地址为 `wss://xiaoa.example.com/worker`。设置页“高级：手动填写域名 / Let's Encrypt”中填写地址、口令和机器名称，证书指纹留空即可使用系统 CA 校验。路线 B 使用域名及 443；可与 IP 网页入口同时存在。

## 已有云端启用 IP 证书和续期排查

```bash
sudo python3 /opt/xiaoa/deploy/configure_ip_tls.py <公网IP> <已有hub端口>
systemctl list-timers xiaoa-ip-cert-renew.timer
journalctl -u xiaoa-ip-cert-renew.service --no-pager
# 使用测试 CA 演练续期和 Nginx 加载，不消耗正式签发额度：
sudo /opt/xiaoa-acme/venv/bin/certbot renew --dry-run --run-deploy-hooks \
  --config-dir /opt/xiaoa-acme/config --work-dir /opt/xiaoa-acme/work \
  --logs-dir /opt/xiaoa-acme/logs --deploy-hook /opt/xiaoa-acme/reload-nginx.sh
```

重复执行保留已分配的网页端口和证书，不轮换连接口令。证书、账号和日志隔离在 `/opt/xiaoa-acme`；现有网站的 `/etc/letsencrypt` 和系统 Certbot 不受影响。续期报错时先检查公网 80、安全组和 Nginx，不能等到证书过期才处理。公开 IP 改变时脚本会拒绝沿用旧状态，需明确迁移；证书不适用于内网 IP。

## 1115 公网端口

网页和 worker 默认共用公网 HTTPS/WSS `1115` 端口，被占用时从 `1116` 起自动选择空闲端口，跳过内部 hub 端口。实际端口会写入网页地址和连接串，后续更新优先复用该端口。内部 hub 默认从 `1004` 起寻找空闲回环端口，不需要在安全组开放。公网 TCP `80` 用于证书签发和续期。请在安全组放行 TCP `80` 和部署后显示的实际公网端口；部署不会停止占用端口的其他服务。

部署完成后，请使用自动生成的网页地址和连接串。

## 本机设置与重连

运行 Windows 小A，打开设置页的“消息连接 → 云端连接”。推荐直接粘贴连接串，机器名称默认使用电脑名，可按需修改；点击“测试连接”确认解析、端口、证书指纹和口令都通过，再保存并重启小A。测试失败会区分连接串格式、端口/服务不可达、证书指纹、TLS 和口令错误。

重装系统或换电脑时，安装小A后粘贴保存的同一连接串即可。不要把连接串发给别人；它等同于 worker 的长期凭据。

## 电脑关机时的能力边界

云端仍可使用服务器上注册的约 50 个工具，主要包括 `code_*` 代码工作台、浏览器、扩展、项目索引、文件读写、记忆和消息等；因此电脑关机时仍能在云端执行代码、改服务器文件和查看日志。依赖 Windows 桌面的 Office COM、桌面点击/鼠标、Windows 系统控制工具无法使用，worker 离线时会明确提示“电脑不在线”。

## 可选：让云端使用浏览器工具

浏览器工具支持两种接入：由小A启动宿主机上的 Chrome/Edge/Chromium，或通过 `XIAOA_BROWSER_DEBUG_PORT` 连接已运行的小A专用 CDP 浏览器。容器浏览器可复用已有调试端口，通常无需另写 `XIAOA_BROWSER_PATH` 转发脚本；调试服务必须仅对本机开放，且不能连接用户的普通浏览器。

如果使用容器，必须把小A的独立浏览器资料目录和所需工作目录挂载进去，并保持宿主机与容器内路径一致。`browser_upload` 按宿主路径上传，下载默认写入隔离工作区的 `downloads`；只接上 CDP、没有文件挂载，会出现网页和截图可用但文件不互通的情况。不要为浏览器挂载完整系统根目录。登录资料目录应持久保存，避免容器重建后丢失。

已有 `XIAOA_BROWSER_DEBUG_PORT` 或 `XIAOA_BROWSER_PATH` 环境配置修改后，需要在适当时机重启 hub 才会生效。浏览器控制器会保持下载设置所用的 CDP 连接，确保文件保存到隔离下载目录；该连接断开后，下次使用会重新设置。


Chromium 不是 hub 的必需依赖。不安装时，约 10 个 `browser_*` 工具会在调用时提示浏览器不可用，其余约 40 个服务器侧工具不受影响。无头 Chromium 通常会占用几百 MB 内存；服务器内存紧张时不要安装或减少并发。

Debian 12 可以直接使用系统包：

```bash
sudo apt-get update
sudo apt-get install -y chromium
```

如果实际系统是 Ubuntu 22.04 或更新版本，不要使用 `apt install chromium-browser`：它通常只是转发到 Snap，包名和启动路径容易让服务误判。Ubuntu 推荐使用官方 Snap：

```bash
sudo snap install chromium
```

小A会自动寻找 `chromium`、`chromium-browser`、`google-chrome`、`google-chrome-stable` 和 `/snap/bin/chromium`。Linux 启动会自动使用 `--headless=new`、`--no-sandbox`、`--disable-dev-shm-usage`，不需要 X display。若安装在其他路径，可在 `/etc/xiaoa-hub.env` 添加 `XIAOA_BROWSER_PATH=/实际路径/chromium`，然后重启 hub。

安装后可在云端对话中依次测试：打开一个公开网页、读取页面快照、点击页面上的无副作用链接。浏览器专用 profile 位于项目数据目录，首次使用不会有现成登录态；不要把个人登录 Cookie 当作云端公共凭据使用。

## 运维与安全

```bash
sudo systemctl status xiaoa-hub
journalctl -u xiaoa-hub -f
sudo systemctl restart xiaoa-hub
```

安全组只开放路线 A 的自定义端口或路线 B 的 80/443；不要暴露后端管理端口。`AGENT_HUB_TOKEN` 是电脑与云端的机器握手口令，`AGENT_WEB_PASSWORD` 是人登录云端网页的密码，两者必须不同。不要把它们或模型/飞书密钥提交到 Git。
